# Hub Navigation Site Discovery

Changes existing SharePoint option 8 label/default behavior; no extra permission-grant task is added. Script filename and task ID stay unchanged for catalog compatibility. Default ReportMode=Navigation; explicit ReportMode=Associations retains the previous direct hub-association report. Earlier Hub-Associated-Sites documentation applies only to Associations mode now.

Select the main hub (same picker as before). Navigation mode reads its TopNavigationBar and explicitly loads submenu Children using Get-PnPProperty (not the display-only -Tree option). Registered hub destinations discovered in navigation are followed recursively; ordinary sites are listed but their menus are not crawled. Main hub is included in the distinct-site list. Navigation origins/trails are retained for evidence and cycles are prevented with a visited-hub set. Ordinary pages/files/libraries are mapped to the containing site collection using longest matching paths from the verified tenant site inventory; this is not a subweb or unique-permission inventory.

Scope excludes homepage Quick Links/webparts, global app-bar navigation, ordinary-site navigation, cross-host/multi-geo crawling, redirects, opaque sharing-link resolution and audience-specific/effective-access simulation. This is the current signed-in admin's readable menu snapshot. Non-web and other-host links are recorded without following them. Unresolved same-host destinations, inaccessible menus, incomplete inventory/hub catalog, and caps yield PartialCoverage. No claim of tenant-wide or universal navigation completeness. Readable registered hubs on other hosts are not crawled; coverage warnings explain the gap. No permission writes or grant suggestions are executed.

Limits: MaxHubDepth=4 linked-hub hops (root=0), MaxHubs=100, MaxNavigationNodes=20000 globally, submenu depth 20. Hitting a traversal cap is explicit. No hidden disk staging; process termination loses unsaved memory. Existing SharePoint token is validated for tenant/account/expiry and reused for hub-site read connections; no device-code fallback, new app registration, cache manipulation or module install.

Display: compact distinct sites, navigation evidence, coverage and metadata. Export remains opt-in using the existing full-filename CSV prompt. Export includes typed RunSummary/Site/NavigationLink/Coverage records in one consistent CSV schema; filter RecordType=Site for the deduplicated site list. Query strings/fragments and opaque sharing-link targets are omitted from exported URLs; no redeemable sharing URL is intentionally exported. Explicit ExportPath and noninteractive behavior follow Phase 1. Independent approved session logging can still persist a summary.

Patch validates current main file hashes, prepares/parses changes before writing, backs up originals outside repository and rolls back write failures. Updates association regressions to request Associations explicitly and adds 20 offline navigation tests (38 tests combined). All tests use mocks; no modules installed/updated or live tenant operations during patching. PowerShell/Pester, full suite and live navigation scans NOT run during generation (PowerShell unavailable). Installer runs the two focused suites if Pester 5 exists. This is an implementation for local validation, not a claim of successful live discovery.
