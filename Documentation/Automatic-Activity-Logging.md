# Automatic activity logging

Activity logs are the approved exception to display-first optional report exports. Core state defaults to automatic file logging (no disk writes during import alone); launcher initializes it without prompts. Default Logs location is %LOCALAPPDATA%/M365AdminToolkit/Logs, using the existing DataRoot/environment override when deliberately configured. The repository path is still blocked by external-output guards. No change to report/CSV save prompts, templates, backups, authentication or SharePoint task behavior.

Logs append to yyyy-MM-dd_<tenant initial domain>.log; no-tenant is used before connection. Filename follows the current tenant/day instead of pinning the entire session to the first tenant. Token/secret-pattern redaction and severity filtering remain. Retention deletion is NOT re-enabled, and existing files are neither moved nor removed. Explicit custom log files remain supported with their existing append safeguards; explicit Disable lasts until re-enabled/reimport/relaunch. File errors disable logging for that session and warn without failing the administrative caller.

Open Log Folder already uses Get-M365LogPath -Folder; the getter now respects a custom selection as well as the standard daily path. Connection Status shows the same current path when default logging is active, or the explicit custom path, or Off after Disable. Its recent PnP app client ID display is preserved. Existing Get-M365TenantInfo -Refresh behavior is unchanged. Status with default logging enabled can initialize the approved Logs folder if it does not yet exist.

Installer verifies nine current-main files, prepares/parses changes before writing, backs up originals outside repo and rolls back write failures. Updates obsolete prompt/opt-in test expectations rather than retaining known failures. Focused tests: 10 new automatic-logging tests, 4 updated default/custom/disable tests, 24 phase-1 output regression tests, 8 PnP-status tests = 46. All filesystem writes during tests are restricted to Pester TestDrive and service reads mocked; no modules installed/updated or live operations during patch installation/testing. Tests, full suite and live startup were NOT run in generation (PowerShell unavailable). Installer runs the four focused test files if Pester 5 exists. Historical opt-in logging documentation is superseded by this decision.
